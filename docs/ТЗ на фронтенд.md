# ТЗ на фронтенд модуля расчёта DV01

Ознакомительная практика, кейс 3. Пользователь моделирует гипотетические позиции в облигациях и оценивает изменение их стоимости при повышении ставки на 1 базисный пункт. Для показа третьего спринта экран работает на тестовом наборе.

## Поля и действия

| Элемент | Требование |
| --- | --- |
| ISIN | Обязательное поле из 12 символов. Пробелы по краям удаляются, буквы переводятся в верхний регистр. Проверяются формат, контрольная цифра и наличие бумаги в справочнике. |
| Способ ввода | Количество бумаг или стоимость позиции в рублях. |
| Количество | Целое ненулевое число. Отрицательное количество означает короткую позицию. |
| Стоимость | Ненулевая сумма в рублях с точностью до копеек. Отрицательная сумма означает короткую позицию. |
| Справочная карточка | После выбора бумаги показываются название, валютный номинал, котировка, курс и тип купона. При вводе количества показывается предварительная стоимость. |
| Добавление и правка | Форма добавляет одну строку за раз. Каждый ряд можно изменить или удалить. При редактировании можно сохранить правку или отменить её. |
| Расчёт | Доступен при наличии позиции и после завершения правки. Таблица показывает стоимость и рассчитанный DV01 по позициям. Рядом выводится общий DV01 с указанием знака. При изменении сценария результат очищается до нового расчёта. |

Предел модуля для количества и суммы равен 10¹². Сценарий содержит до 100 позиций. Некорректный ввод сопровождается сообщением у формы и сохраняет текущие строки. Сценарий хранится на странице до её обновления.

## Данные и приёмка

В тестовом справочнике есть рублёвая, валютная и плавающая облигации. Бумаги и котировки вымышлены. Экран получает каталог из SQLite через HTTP API. Расчёт выполняется на Python. Клиент использует локальную оценку стоимости в форме, итоговые значения приходят с сервера.

1. Добавить рублёвый лонг из 10 бумаг с котировкой 95% и валютный шорт из 2 бумаг. Стоимости 9 500 ₽ и −25 250 ₽. Итог после расчёта +1,98 ₽.
2. Изменить первую строку на 12 бумаг. Убедиться, что старый итог сброшен и после расчёта новый итог равен +1,31 ₽.
3. Удалить валютную строку. После расчёта итог должен быть −3,99 ₽.
4. Ввести для первой бумаги 9 500 ₽ напрямую и проверить, что её DV01 совпадает с результатом для 10 штук.
5. Проверить отказ для неизвестной бумаги, неверной контрольной цифры, нуля и дробного количества.

Общий DV01 считается как сумма знаковых результатов по введённым позициям в рублях. Это предварительное правило агрегации до подтверждения экспертом. Для оценки всей торговой книги требуется её фактический состав.
